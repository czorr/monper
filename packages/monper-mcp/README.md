# monper-mcp

**Your logged-in web, as MCP tools.**

Every AI hits the same wall: it can read the public web and nothing else. Your invoices, your
dashboards, your internal tools, your admin panels — all behind a login that no cloud agent can
cross. That's why a whole industry builds integrations and OAuth apps for data that is *already
rendered* in a browser tab that is *already authenticated*.

Your browser is the only piece of software on your machine that is already signed in to
everything you use. `monper-mcp` makes that available to any MCP client — Claude Code, Cursor,
your own scripts — **without an API, without OAuth, and without anything leaving your machine**.

```jsonc
// Claude Code / Cursor MCP config
{
  "mcpServers": {
    "monper": { "command": "npx", "args": ["-y", "monper-mcp"] }
  }
}
```

Then: *"Open my AWS billing page and tell me what changed since last month."*

## Requirements

[Monper](https://github.com/czorr/monper) running, with **Settings → MCPs → Serve Monper over
MCP** turned on. The token is generated by Monper and read from its data directory: there is
nothing to copy.

## Tools

| Tool | What it does |
|---|---|
| `open_page` | Opens a URL **with your session**, waits for load. Background by default — it doesn't steal the tab you're looking at. |
| `read_page` | Readable text, with nav/header/footer stripped. The cheap way to read. |
| `list_tabs` | What's open. |
| `click` | Clicks by visible text. |
| `fill` | Types into a field by label. |
| `screenshot` | When layout matters. |

## What it will never do

- **Touch the vault or autofill.** Secrets belong to the user; no tool can request one.
- **Type into a password field.** `fill` refuses, on purpose.
- **Turn itself on.** Only the user enables the bridge, in Monper's own UI, and a pill stays
  visible in the sidebar the whole time it's active.

## The security model, stated plainly

With the bridge on, a client that has the token can browse to the sites where you're signed in
and read what they show. That is what controlling a browser *means* — it isn't a leak, it's the
feature. What we do about it:

- **127.0.0.1 only.** Never the local network.
- **Bearer token** in a header, never in the URL (URLs end up in logs and history).
- **A native prompt the first time each client sends a command**, naming it. Approval lasts for
  the session only — closing Monper forgets it.
- **Never persisted as on.** Every session you turn it on yourself.

## Config

| Variable | Default |
|---|---|
| `MONPER_PORT` | `9223` |
| `MONPER_TOKEN` | read from Monper's `remote.json` |
| `MONPER_CLIENT_NAME` | the name shown in the approval prompt |
